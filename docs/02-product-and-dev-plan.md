# Kiwi Finance — 产品方案与开发计划

> 版本 v0.1 · 2026-09 · 配套阅读：[`01-market-research.md`](./01-market-research.md)

---

## 1. 产品定义

**一句话**：Kiwi 是给不想连银行、也不想每年花 $100 的人做的 AI 记账本 —— 拍一张收据、截一张图、说一句话，账就记好了。

**首发市场**：美国 / 加拿大 / 澳洲 / 英国（英文），iOS 优先
**首发人群**：25–40 岁、有记账意愿但被 Mint 关停或 $99 定价劝退的人；现金/多渠道消费比例高的人
**北极星指标**：**周活跃用户中，每周记账 ≥3 天的比例**（不是下载量，不是 DAU）

## 2. 功能范围（P0 / P1 / P2）

### P0 — MVP 必须有（无此不成立）

| # | 功能 | 说明 | 为什么是 P0 |
|---|---|---|---|
| 1 | **快速手动记账** | 数字键盘 + 分类 + 备注，3 秒完成；这是兜底路径 | 咔皮的最大差评就是手动入口太深 |
| 2 | **AI 收据/截图识别** | 拍照或从相册/共享菜单选图 → 提取商家、金额、日期、税、条目 → 预填 | 核心差异化 |
| 3 | **AI 语音 / 自然语言记账** | "coffee 5 bucks and 32 for gas" → 拆成 2 条并分类 | 核心差异化（抄咔皮"一句话多笔"） |
| 4 | **iOS 系统级入口** | Share Extension（任意 App 截图/收据直接分享给 Kiwi）+ Shortcuts/App Intents + 背部轻点 | **入口必须在 App 之外**，否则留存无解 |
| 5 | **自动分类 + 学习** | LLM 分类 + 用户修正后写入规则，同商家下次自动命中 | 分类准确率是留存生命线 |
| 6 | **账户与余额** | 现金/借记/信用/储蓄，手动余额校准，转账不计收支 | 记账内核，缺了就是"记流水"不是"记账" |
| 7 | **预算（精确到天）** | 月预算自动摊到每日；超支后自动重排剩余可用额度 | **最强的每日回看理由**（抄咔皮） |
| 8 | **统计与月报** | 分类饼图、趋势、Top 商家、月度对比 | 记账的兑现时刻 |
| 9 | **本地优先 + 云同步** | SQLite 本地库；软删除 + 变更日志，**永不硬删** | 直接打咔皮"记录被误删"的口碑裂缝 |
| 10 | **一键导出** | CSV / JSON 全量导出，无付费墙 | 信任叙事（抄钱迹）；也是苹果审核加分项 |
| 11 | **主屏小组件** | 今日剩余预算 + 一键记账 | 无需打开 App 即可看到"回看理由" |

### P1 — 商业化与留存（MVP 后 4–6 周）

- **订阅付费墙**：免费档（每月 30 次 AI 识别 + 1 个账本）/ Pro 档（无限 AI + 多账本 + 银行聚合）
- **AI 月度复盘**：不是图表，是**一段话的诊断** —— "你这个月外卖比上月多 $180，主要集中在周三和周四晚上"
- **智能提醒**：预算过半、异常大额、周复盘推送（推送策略必须克制，否则卸载）
- **多币种**（吃华人/跨境人群，见调研 §4）：记录当时汇率 + 实际到账
- **循环交易识别**：自动识别订阅（Netflix/Spotify/健身房）并提醒
- **邮件收据解析**：转发收据邮件到专属地址 → 自动入账（Amazon/Uber/DoorDash）

### P2 — 扩张（3–6 个月后）

- **银行聚合**（Teller → 后期 Plaid/Quiltt 冗余）
- **家庭 / 情侣共享账本**（付费转化率最高的功能之一，对标 Monarch）
- **Android 版**
- **Web / 桌面端**
- **中国版**（独立分支：无障碍自动记账 + 微信/支付宝截图，见调研 §3）

## 3. 技术方案

### 3.1 技术栈（推荐方案）

| 层 | 选型 | 理由 |
|---|---|---|
| **客户端** | **Expo (React Native) + TypeScript** | 一套代码覆盖 iOS→Android；差异化在 AI 而非炫酷动效；迭代速度最快 |
| 本地数据库 | **SQLite**（`op-sqlite`）+ Drizzle ORM | 本地优先、离线可用、快 |
| iOS 原生模块 | **Swift**：Share Extension、App Intents（Shortcuts / 背部轻点）、WidgetKit | 这三个必须原生，无替代方案 |
| **后端** | **Supabase**（Postgres + Auth + RLS + Storage） | Auth/多设备同步/文件存储开箱即用，省 3–4 周 |
| **AI 服务** | 独立 **Node/Fastify** 服务（Fly.io 或 Railway） | **API Key 绝不能进客户端**；也便于做限流、缓存、成本控制 |
| 订阅计费 | **RevenueCat** | 跨平台内购/订阅状态管理的事实标准 |
| 监控 | **Sentry**（崩溃）+ **PostHog**（行为漏斗） | 留存分析必需 |
| 银行聚合（P2） | **Teller** → Plaid | 见调研 §2.4 成本表 |

> **备选方案**：如果 12 个月内明确只做 iOS、且要对标 Copilot 的设计水准，改用 **SwiftUI 原生**。代价是 Android 需要重写一遍（约 +8 周）。

### 3.2 AI 管线设计

三层模型分工（按成本/能力匹配，非一刀切）：

| 任务 | 模型 | 单价（输入/输出，每百万 token） | 说明 |
|---|---|---|---|
| **交易分类**（高频、简单） | `claude-haiku-4-5` | $1 / $5 | 量最大，用最便宜的；分类体系走 **prompt caching** |
| **收据/截图提取**（多模态） | `claude-sonnet-5` | $2 / $10 | 需要视觉理解 + 结构化输出（`output_config.format`）；准确率优先 |
| **月度复盘 / 财务洞察**（低频、推理重） | `claude-opus-5` | $5 / $25 | 每月每人 1–2 次，值得用最强的 |

**三个成本杠杆**
1. **Prompt caching**：分类体系 + 用户历史商家表放在提示词前缀并缓存 → 输入 token 成本大幅下降
2. **Batch API**：夜间批量重分类、月报生成走批处理 → **成本减半**
3. **本地规则优先**：命中"商家→分类"规则表的交易**根本不调模型**（预计可拦截 60–70% 的调用）

**单用户 AI 成本估算**（活跃用户，月 200 笔交易 + 60 次截图/收据）

| 项目 | 估算 |
|---|---|
| 分类（扣除规则命中后约 70 次） | ~$0.07 / 月 |
| 收据与截图提取（60 次） | ~$0.36 / 月 |
| 月度复盘（1 次） | ~$0.11 / 月 |
| **合计** | **≈ $0.55 / 月 = $6.6 / 年** |

**毛利测算**（定价 $39/年）

| 项目 | 金额 |
|---|---|
| 收入 | $39.00 |
| App Store 抽成（首年 30%） | −$11.70 |
| AI 成本 | −$6.60 |
| Teller 银行聚合（仅连接用户，3 账户） | −$10.80 |
| Supabase / 服务器 / 监控（摊薄） | −$1.50 |
| **净毛利** | **$8.40（21%）** — 若用户不连银行则为 **$19.20（49%）** |

> **重要结论**：$39/年 在"连银行"场景下毛利偏薄。建议：
> - **$39/年 = AI 记账版（不含银行聚合）**
> - **$69/年 = Pro 版（含银行聚合 + 家庭共享）**
> 既守住价格空档，又让高成本功能自己覆盖成本。

### 3.3 核心数据模型（简化）

```
ledgers        账本（个人 / 家庭 / 旅行）
accounts       账户（现金/借记/信用/储蓄）· 币种 · 当前余额
transactions   交易 · 金额 · 币种 · 原始币种与汇率 · 时间 · 账户 · 分类 ·
               商家 · 备注 · 标签 · 来源(manual|ocr|voice|bank|email) ·
               ai_confidence · deleted_at(软删除)
categories     分类树（系统预置 + 用户自定义）
merchants      商家 · 归一化名称 · 默认分类
rules          自动分类规则（商家/关键词 → 分类）
budgets        预算 · 周期 · 分类 · 金额 · 每日摊销策略
attachments    收据图片（Supabase Storage）
sync_log       变更日志（append-only，用于多设备同步与恢复）
```

**两条硬性设计原则**
1. **永不硬删除**：所有删除写 `deleted_at`，`sync_log` 只追加不覆写 → 任何"记录消失"都可恢复
2. **金额用整数分存储**（`INTEGER`），永不使用浮点数

### 3.4 隐私与合规

- 收据图片：**本地识别后可选不上传**；上传的默认 30 天后删除
- Supabase **行级安全（RLS）** 全表开启，用户只能读写自己的数据
- 明确的隐私政策 + Apple 隐私标签如实填写（金融类审核重点）
- **不做任何投资建议措辞**（App Store 审核 + 金融监管红线）
- 送模型的数据做最小化：只传必要字段，不传姓名/账号全文

## 4. 开发计划

### Phase 0 — 验证与准备（第 1–2 周）

| 任务 | 产出 |
|---|---|
| 收集 **500+ 条真实收据/支付截图** 建评测集 | `eval/receipts/` 标注数据集 |
| 跑通 AI 提取 Spike，测准确率 | 准确率报告；**<92% 则调整方案再开工** |
| 分类体系设计（约 12 个一级 + 60 个二级） | `categories.json` |
| 设计系统 + 核心 5 个页面高保真稿 | Figma / 设计稿 |
| 竞品 App 实际使用（Copilot、Monarch 各用 1 周） | 体验笔记 |

**门槛**：AI 提取准确率 ≥92%，否则重新评估技术路线。

### Phase 1 — MVP（第 3–10 周）

| 周 | 内容 |
|---|---|
| 3–4 | 项目脚手架、本地 SQLite 数据层、账户/交易/分类 CRUD、手动记账流 |
| 5–6 | AI 服务（提取 + 分类 + 规则引擎）、拍照/相册识别流、语音记账 |
| 7 | iOS Share Extension + Shortcuts/App Intents + 背部轻点 |
| 8 | 预算（日摊销）+ 统计报表 + 小组件 |
| 9 | Supabase 同步、账号体系、导出 |
| 10 | 打磨、埋点、TestFlight 内测（目标 50 名种子用户） |

**Phase 1 交付**：可日常使用的 iOS App，全功能免费，无付费墙。

### Phase 2 — 商业化与留存（第 11–16 周）

| 周 | 内容 |
|---|---|
| 11–12 | RevenueCat 订阅接入、付费墙、免费额度控制 |
| 13 | AI 月度复盘 + 智能提醒 + 循环交易识别 |
| 14 | 多币种 + 邮件收据解析 |
| 15 | 性能/稳定性、崩溃率 <0.5%、ASO、落地页 |
| 16 | **App Store 正式上线** |

**Phase 2 门槛**：内测用户 4 周留存 ≥35%，否则先修留存再上线。

### Phase 3 — 扩张（第 17–28 周）

- Teller 银行聚合接入（Pro 档）
- 家庭/情侣共享账本
- Android 版（Expo 复用，约 4 周）
- Web 端只读仪表盘

### Phase 4 — 中国版（视 Phase 2/3 结果决定）

独立分支：Android 无障碍自动记账、微信/支付宝截图识别、微信登录、App 备案与 PIPL 合规、多渠道安卓上架。

## 5. 验证指标与决策门

| 阶段 | 指标 | 门槛 | 不达标怎么办 |
|---|---|---|---|
| Phase 0 | AI 提取准确率 | ≥92% | 换模型/加后处理规则，或降级为"AI 预填 + 人工确认" |
| Phase 1 | 种子用户周记账天数 | ≥3 天/周 | 重做录入流，不要加功能 |
| Phase 2 | 4 周留存 | ≥35% | 暂停上线，专攻"每日回看理由" |
| Phase 2 | 免费→付费转化 | ≥3% | 调整免费额度和付费墙位置，而非降价 |
| Phase 3 | 月流失率（付费） | <5% | 检查银行聚合断连率（这是海外产品第一大流失原因） |

## 7. 待决策项

1. **技术栈拍板**：Expo（跨平台，推荐）还是 SwiftUI（iOS 体验更好，Android 需重写）
2. **定价拍板**：单档 $39/年，还是 $39 / $69 双档（推荐双档，理由见 §3.2）
3. **免费档额度**：每月 30 次 AI 识别是否合适（需内测数据校准）
4. **品牌**："Kiwi" 在英文语境下指猕猴桃/新西兰人/几维鸟 —— 需确认商标可用性及 App Store 同名冲突
5. **是否做邮件解析**：需要一个专属收件域名和邮件解析服务（增加合规面）
