## 1. 产品概述

### 1.1 一句话定义

Kiwi Finance 是**个人财务数据层** —— 记录极简到只需截个图；分析强到可以用一句话生成任何报表；数据随时可以交给用户自己的 AI。

### 1.2 它不是什么

不是又一个记账 App。工具层已饱和：免费产品（钱迹、Apple Wallet）把底价打到 0，付费产品（Copilot / Monarch / YNAB）集体停在 $95–110/年。Kiwi 的位置在两者之间，靠的不是价格，是**结构性能力差异**。

### 1.3 目标用户

| 优先级 | 人群 | 特征 |
|---|---|---|
| **主要** | 海外英文市场（美/加/英/澳）25–40 岁 | 有记账意愿，被 $99 定价或"必须连银行"劝退；现金与多渠道消费比例高 |
| **种子** | 跨境生活者 | 留学生、外派、跨境电商、数字游民、海外持股。多币种是刚需，现有产品几乎无人做对 |
| **第二阶段** | 中国大陆用户 | 独立分支，见 §12 Phase 4 |

### 1.4 价值主张

1. **极简的记录入口** —— 六条捕获路径，怎么方便怎么来
2. **专为财务优化的 AI harness** —— 数字由确定性引擎算，模型只负责理解意图和写解读
3. **数据是你的** —— MCP 连接、全量导出、Skill 导出，随时可以带走

### 1.5 北极星指标

**周活跃用户中，每周记账 ≥3 天的比例。**
不是下载量，不是 DAU。记账 App 的历史共性是"下载高、次月留存崩"，只有记录频率能预测留存。

## 2. 设计原则（约束性）

任何与之冲突的方案一律否决。这三条不是偏好，是产品的物理边界。

| # | 原则 | 具体含义 |
|---|---|---|
| **P-1** | **数字永远不来自模型** | LLM 只输出类型化的查询规格；所有计算由确定性引擎完成；每个数字可点击溯源到具体交易行。模型物理上没有产生数字的路径 |
| **P-2** | **多币种是地基，不是功能** | 第一行 schema 就带原币种金额 + 汇率 + 汇率来源 + 本位币金额。单币种是多币种的特例 |
| **P-3** | **用户的数据属于用户** | MCP 连接、全量导出、Skill 导出三条通道永远开放，导出无付费墙 |

## 3. 目标与非目标

### 3.1 本期目标

- 让"记录一笔账"的成本降到接近零（截图/说一句话即可）
- 让用户不提问就能看懂自己的财务状况（8 个标准报表）
- 让用户能用自然语言生成任何自定义报表，并把数据交给自己的 AI
- 多币种从第一天可用

### 3.2 明确不做

| 不做 | 原因 |
|---|---|
| 投资组合追踪 | Monarch / Copilot 的深水区，投入产出比低 |
| 贷款 / 理财产品导流 | 毁信任，且触发金融合规 |
| 社交 feed | 记账是私密行为 |
| MVP 阶段的 Android | 海外 iOS 付费率高 2–3 倍 |
| 模型微调 / 二次开发 | 中国版会因此触发 3–6 个月的大模型备案（见 §10.3） |

## 5. 功能需求 · 捕获层（FR-CAP）

## 7. 功能需求 · 分析与 AI Harness（FR-ANA）

> 核心机制：**text-to-spec, not text-to-answer**。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-ANA-01** | 指标引擎 | P0 | 约 40 个版本化命名指标，每个是纯函数，有单元测试与黄金数据集；返回值带单位、币种、口径 |
| **FR-ANA-02** | Report Spec 契约 | P0 | 有 JSON Schema 定义；Planner 输出必须通过校验，**非法即拒绝重出，不降级不猜** |
| **FR-ANA-03** | 8 个标准报表 | P0 | 月度复盘 / 订阅审计 / 跨境与汇率暴露 / 旅行账单结算 / 大额异常排查 / 预算重规划 / 报税准备包 / 年度回顾 |
| **FR-ANA-04** | 标准报表预计算 | P0 | 首屏渲染 < 300ms；不走 LLM |
| **FR-ANA-05** | 数字可溯源 | P0 | 报表中任意数字可点击，展开到构成它的交易行列表 |
| **FR-ANA-06** | Narrator 事实约束 | P0 | 叙述只能引用事实集中的数字；每个论断标注来源 block；**输出中不得出现事实集以外的数值** |
| **FR-ANA-07** | 自然语言生成个性化报表 | P1 | 用户用一句话描述需求，生成可用报表；Spec 校验通过率 ≥ 90% |
| **FR-ANA-08** | 报表保存与重跑 | P1 | 保存的报表可命名、可定时（周/月）、结果可复现 |
| **FR-ANA-09** | 月度复盘推送 | P1 | 每月生成一段**文字诊断**（不是图表），如"外卖比上月多 $180，集中在周三周四晚上" |
| **FR-ANA-10** | 智能提醒 | P1 | 预算过半、异常大额、订阅涨价；推送策略克制，用户可逐项关闭 |
| **FR-ANA-11** | 数据质量提示 | P2 | 未分类比例、低置信记录数、疑似重复，在设置页可见并可批量处理 |

## 10. 非功能需求（NFR）

### 10.1 性能

| 编号 | 需求 | 目标 |
|---|---|---|
| **NFR-P-01** | 规则命中的分类 | < 50ms，不走 LLM，覆盖约 65% 的交易 |
| **NFR-P-02** | 标准报表首屏 | < 300ms（预计算 + 缓存） |
| **NFR-P-03** | 截图 / 收据提取 | 2–4s |
| **NFR-P-04** | 个性化报表生成 | 4–8s |
| **NFR-P-05** | 月度复盘 | 离线批处理，不阻塞用户 |
| **NFR-P-06** | 崩溃率 | < 0.5% |

> 原则：**LLM 用在"理解意图"和"写字"，不用在"算数"和"重复劳动"。**

### 10.2 安全与隐私

| 编号 | 需求 |
|---|---|
| **NFR-S-01** | 收据与邮件是**不可信输入**。提取模型零工具权限、以纯数据方式处理、输出走严格 schema 校验 |
| **NFR-S-02** | Prompt injection 对抗用例集拦截率 **100%**，不通过不进 Phase 1 |
| **NFR-S-03** | API Key 绝不进客户端，全部模型调用经服务端 |
| **NFR-S-04** | 收据图片支持"识别后不上传"；已上传的默认 30 天后删除 |
| **NFR-S-05** | 送模型的数据最小化，不传姓名与完整账号 |
| **NFR-S-06** | MCP 令牌短有效期 + 刷新轮换 + 严格 redirect URI 匹配 |

### 10.3 合规

| 编号 | 需求 |
|---|---|
| **NFR-C-01** | 产品内**不出现任何投资建议措辞**（App Store 审核 + 金融监管红线） |
| **NFR-C-02** | Apple 隐私标签如实填写 |
| **NFR-C-03** | **中国版：只调用已备案的国产模型 API，不做微调或任何二次开发** —— 因此只需 AI 应用登记，可避开 3–6 个月的大模型备案 |
| **NFR-C-04** | 中国版所有自由文本字段过内容安全接口（敏感问题拒答率 ≥ 95%） |
| **NFR-C-05** | 境外模型不得用于服务中国大陆用户（无合规路径） |

### 10.4 可靠性

| 编号 | 需求 |
|---|---|
| **NFR-R-01** | 永不硬删除；任何"记录消失"可恢复 |
| **NFR-R-02** | 离线完全可用 |
| **NFR-R-03** | 模型供应商故障时自动降级到备用适配器 |

## 11. 技术方案摘要

> 完整设计见 [`03-ai-native-architecture.md`](./03-ai-native-architecture.md) 与 [`04-model-strategy.md`](./04-model-strategy.md)。

### 11.1 架构

```
捕获层 → 多币种账本内核 → 指标引擎 → AI Harness → 标准报表 / 个性化报表 / MCP Server

AI Harness：
意图 → Planner(LLM) → Report Spec(JSON) → schema 校验 → 指标引擎(确定性)
     → 事实集 → Narrator(LLM，只引用事实) + 渲染器(确定性)
```

### 11.2 技术栈

| 层 | 选型 |
|---|---|
| 客户端 | Expo (React Native) + TypeScript（待决策 D-1） |
| 本地库 | SQLite（`op-sqlite`）+ Drizzle |
| iOS 原生 | Swift：Share Extension · App Intents · WidgetKit |
| 后端 | Supabase（Postgres + Auth + RLS + Storage） |
| AI / 指标服务 | Node + Fastify，同时是 MCP Server 宿主 |
| 模型路由 | **ModelRouter**：`{task, region, tier} → {provider, model, params}` |
| 汇率 | ECB / Frankfurter 日频基准 + 用户按账单覆盖 |
| 计费 / 监控 | RevenueCat · Sentry · PostHog |

### 11.3 模型选型（双轨）

| 负载 | 海外 | 中国 |
|---|---|---|
| 交易分类 | Gemini 2.5 Flash-Lite | Qwen-Turbo |
| 收据/截图提取 | **Gemini 3.7 Flash** | qwen-vl-ocr（专用）+ 文本模型归类 |
| 低置信复核 | Gemini 3.1 Pro | GLM-OCR |

### 15.2 术语表

| 术语 | 含义 |
|---|---|
| **DraftTransaction** | 捕获层的统一输出，含字段、confidence、provenance，确认后成为正式交易 |
| **Provenance** | 记录来源凭证：哪张图、哪封邮件、哪次 API 调用。永久保存 |
| **Report Spec** | LLM 与指标引擎之间的类型化 JSON 契约，描述"要算什么"而非"答案是什么" |
| **事实集** | 指标引擎执行 Report Spec 后产出的、带口径的数字集合。Narrator 只能引用它 |
| **成交汇率** | 银行卡账单上真实发生的汇率（含加点）。回答"我实际花了多少" |
| **报表汇率** | 统一使用的中间价，用于跨期跨币种对比 |
| **Skill** | 符合 agentskills.io 规范的能力包（SKILL.md + 资源），可被 Claude/Codex 等客户端加载 |
| **MCP** | Model Context Protocol，让用户的 AI 客户端连接到 Kiwi 读取数据 |
| **ModelRouter** | 模型抽象层，把 `{任务, 地区, 档位}` 映射到具体供应商与模型 |
