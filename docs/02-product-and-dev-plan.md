## 1. 产品定义

**一句话**：Kiwi 是你的个人财务数据层 —— 记录极简到只需截个图，分析强到可以用自然语言生成任何报表，数据随时可以交给你自己的 AI。

**核心价值主张**
1. **极简的记录入口**：截图 / 拍照 / 邮件 / API / 语音 / 手动，六条路，怎么方便怎么来
2. **专为财务优化的 AI harness**：数字由确定性引擎算，模型只负责理解意图和写解读 —— 简单、清晰、专业、明了
3. **数据是你的**：MCP 连接、全量导出、Skill 导出，随时可以带走

**首发市场**：美 / 加 / 英 / 澳（英文），iOS 优先，**多币种从第一天可用**
**首发人群**：跨境生活者、多币种消费者、有记账意愿但被 $99 定价和"必须连银行"劝退的人
**北极星指标**：周活跃用户中，**每周记账 ≥3 天**的比例

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 客户端 | **Expo (React Native) + TypeScript** | 一套代码覆盖 iOS→Android；差异化在 AI 而非炫酷动效 |
| 本地库 | **SQLite**（`op-sqlite`）+ Drizzle | 本地优先、离线可用、快 |
| iOS 原生 | **Swift**：Share Extension · App Intents · WidgetKit | 这三块无替代方案 |
| 后端 | **Supabase**（Postgres + Auth + RLS + Storage） | 省 3–4 周 |
| AI / 指标服务 | 独立 **Node + Fastify**（Fly.io / Railway） | API Key 不进客户端；也是 MCP Server 的宿主 |
| MCP | **TypeScript MCP SDK**，Streamable HTTP + 无状态 JSON | 与 AI 服务同进程，共用指标引擎 |
| 汇率 | ECB / Frankfurter（免费日频）+ 用户覆盖 | 历史汇率永久缓存 |
| 计费 | RevenueCat | 跨平台订阅状态管理 |
| 监控 | Sentry + PostHog | 留存漏斗必需 |
| 银行聚合（P2） | Teller → Plaid | 见调研 §2.4 |

> 备选：若 12 个月内只做 iOS 且要对标 Copilot 的设计水准，改用 SwiftUI 原生，代价是 Android 重写（约 +8 周）。

## 4. 单位经济

### 4.1 AI 成本（活跃用户，月 200 笔交易 + 60 次识别）

| 任务 | 模型 | 单价（输入/输出，每百万 token） | Plus 档 | Pro 档 |
|---|---|---|---|---|
| 交易分类（规则拦截 60–70% 后） | `claude-haiku-4-5` | $1 / $5 | $0.07 | $0.07 |
| 收据与截图提取（多模态） | `claude-sonnet-5` | $2 / $10 | $0.36 | $0.36 |
| 月度复盘叙述（Batch，五折） | `claude-opus-5` | $5 / $25 | $0.06 | $0.06 |
| 个性化报表（Planner + Narrator） | `claude-sonnet-5` | $2 / $10 | $0.38（10 次） | $1.14（30 次） |
| **月合计** | | | **$0.87** | **$1.63** |
| **年合计** | | | **$10.4** | **$19.6** |

**三个成本杠杆**：本地规则优先（拦截 60–70% 的分类调用）· Prompt caching（分类体系与商家表放前缀）· Batch API（月报与夜间重分类，成本减半）。

> 💡 **MCP 是成本上的白送**：外部 AI 通过 MCP 查询时，推理由**用户自己的 Claude / ChatGPT 订阅**承担，我们只出数据库查询和带宽。一个高价值功能，边际成本接近零。

## 5. 开发计划

### Phase 0 — 设计与验证（第 1–3 周）

| 任务 | 产出 |
|---|---|
| 收集 500+ 条真实收据/截图（**含多币种、多语言**）建评测集 | `eval/` 标注数据集 |
| AI 提取 Spike，测准确率 | 准确率报告 |
| **Prompt injection 对抗测试**（恶意小票/邮件） | 防护提示词模板 + 用例集 |
| **Report Spec JSON Schema 设计** | `spec/report-spec.schema.json` |
| **指标库 v0：12 个核心指标** + 黄金数据集 | 带测试的指标函数 |
| 分类体系（12 个一级 + 60 个二级）· 多币种数据模型定稿 | `categories.json` · schema DDL |
| 设计系统 + 核心 6 个页面高保真稿 | 设计稿 |

**🚦 门槛**：AI 提取准确率 ≥ 92%（含多币种样本）· injection 用例 100% 拦截 · Spec schema 能表达 8 个标准报表。任一不达标就重估路线。

### Phase 1 — MVP（第 4–14 周）

| 周 | 内容 |
|---|---|
| 4–5 | 脚手架 · **多币种账本内核** · 事件日志 · 手动记账流 |
| 6–7 | 捕获层：截图/拍照/语音提取管线 · 待确认队列 · 分类规则引擎 |
| 8 | 邮件转发入账 · 个人 API / Webhook |
| 9 | iOS Share Extension · App Intents · 背部轻点 · 小组件 |
| 10–11 | **指标引擎（40 个指标）** · 数字溯源 |
| 12 | **8 个标准报表**（预计算 + 缓存）· 预算日摊销 |
| 13 | Supabase 同步 · 账号体系 · 全量导出 |
| 14 | 打磨 · 埋点 · TestFlight 内测（50 名种子用户） |

**交付**：可日常使用的 iOS App，多币种可用，全功能免费。
**🚦 门槛**：种子用户周记账 ≥ 3 天。不达标就重做捕获流，**不加功能**。

### Phase 2 — AI 原生能力与商业化（第 15–22 周）

| 周 | 内容 |
|---|---|
| 15–16 | **Planner：自然语言 → Report Spec** · 渲染器 · 事实集约束的 Narrator |
| 17 | **Skill 化**：报表保存/命名/定时/导出为 SKILL.md |
| 18–19 | **MCP Server + OAuth 2.1**（PKCE + DCR）· 作用域 · 审计日志 |
| 20 | **三客户端真实联调**：Claude Web / Claude Desktop / ChatGPT |
| 21 | RevenueCat 订阅 · 三档付费墙 · 额度控制 · 智能提醒 |
| 22 | 稳定性（崩溃率 <0.5%）· ASO · 落地页 · **App Store 上线** |

**🚦 门槛**：4 周留存 ≥ 35% 且免费→付费转化 ≥ 3%。不达标先修留存再上线。

### Phase 3 — 扩张（第 23–34 周）

Teller 银行聚合（Pro 档）· 家庭 / 情侣共享账本 · Android（Expo 复用约 4 周）· Web 只读仪表盘 · Skill 社区分享。

**监控**：付费月流失 < 5%；重点查银行断连率（海外产品第一大流失原因）。

### Phase 4 — 中国版（视前三阶段结果决定）

独立分支：Android 无障碍自动记账 · 微信/支付宝截图识别 · 微信登录 · App 备案与 PIPL 合规 · 多渠道安卓上架。

## 6. 决策门与指标

| 阶段 | 指标 | 门槛 | 不达标怎么办 |
|---|---|---|---|
| Phase 0 | AI 提取准确率（含多币种） | ≥ 92% | 换模型/加后处理，或降级为"AI 预填 + 人工确认" |
| Phase 0 | Prompt injection 拦截率 | 100% | 不通过不进 Phase 1，无例外 |
| Phase 1 | 种子用户周记账天数 | ≥ 3 天 | 重做捕获流，不加功能 |
| Phase 1 | 标准报表首屏延迟 | < 300ms | 加预计算，别加缓存补丁 |
| Phase 2 | 4 周留存 | ≥ 35% | 暂停上线，专攻每日回看理由 |
| Phase 2 | 免费→付费转化 | ≥ 3% | 调整免费额度与付费墙位置，而非降价 |
| Phase 2 | 个性化报表 Spec 校验通过率 | ≥ 90% | 补 Planner 的 few-shot 与 schema 说明 |
| Phase 3 | 付费月流失 | < 5% | 查银行断连率 |

| **Plus** | **$49** | 无限 AI 捕获 · 全部 8 个标准报表 · **多币种** · 每月 10 份个性化报表 |

## 8. 风险

| 风险 | 级别 | 应对 |
|---|---|---|
| **留存崩塌**（行业通病：次月留存 <20%） | 🔴 高 | 每日预算余额 + 小组件 + 每周复盘推送 |
| **数字幻觉**（一次就足以致命） | 🔴 高 | Report Spec 架构从物理上切断模型产出数字的路径 + 每个数字可溯源 |
| AI 提取准确率不达标 | 🔴 高 | 500+ 条评测集，<92% 不上线；永远保留 1 秒可改的手动修正 |
| **Prompt injection**（收据/邮件是不可信输入） | 🟠 中高 | 提取模型零工具权限 + 严格 schema 输出 + 对抗用例集 |
| **复杂度膨胀**（"什么都能问，什么都不好用"） | 🟠 中高 | 8 个标准报表必须做到不用提问就够用；个性化是补充不是主路径 |
| MCP OAuth 跨客户端兼容性 | 🟡 中 | Phase 2 在三个客户端各做一遍真实联调 |
| 聚合成本失控 | 🟡 中 | 聚合放 Pro 档；先用 Teller；按连接数计费 |
| 苹果审核（金融类从严） | 🟡 中 | 不碰"投资建议"措辞；隐私标签如实填写 |
| 大厂降维（Apple Wallet 内建预算） | 🟡 中 | 多币种 + 跨账户 + 数据可导出到自有 AI，Apple 结构上覆盖不到 |

## 10. 待决策

1. **技术栈** —— Expo（跨平台，推荐）还是 SwiftUI（iOS 更好，Android 需重写，+8 周）
2. **本位币策略** —— 是否首版就支持"双本位币视图"（生活本位币 + 汇报本位币），还是先单本位币可切换
3. **免费档额度** —— 每月 30 次 AI 识别 + 3 个标准报表是否合适，需内测校准
4. **MCP 是否下放到 Plus 档** —— 放 Pro 独占（利于定价）vs 放 Plus（利于口碑传播与生态卡位）
5. **品牌** —— "Kiwi" 在英文语境指猕猴桃 / 新西兰人 / 几维鸟，需确认商标可用性与 App Store 同名冲突
6. **邮件解析域名** —— 需专属收件域名与解析服务，会增加合规面
